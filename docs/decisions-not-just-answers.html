Decisions, not just answers

An agent that works for you makes dozens of judgment calls an hour. JDE is where Titan makes them, how we measure them, and the record of what it decided. Open source, MIT licensed, and running behind the agents our beta customers use every day.

The thing nobody warns you about

An AI agent that does real work will tell you it finished. Sometimes it did not.

"Done. I researched all five suppliers and wrote the comparison."

No file was written. Two suppliers were checked. The comparison is your own request, rearranged into a sentence that sounds like an answer. It arrives in the same confident tone the agent uses when it genuinely succeeded, which is what makes it dangerous.

You cannot catch that with ordinary code. Whether a claim matches its evidence is a judgment. So is whether "who has this part near me" is a local question or a price question. So is whether an answer that says nobody carries something has earned the right to say so.

Most teams answer those by asking a large model in prose, parsing the prose, inventing a confidence threshold on the spot, and keeping no record. That holds until the fourth such decision. Then the same number lives in four files, no two agree on what to do when the answer is uncertain, and nobody can say what the agent decided yesterday or why.

What we built instead

JDE asks the judgment as a typed question, gets a calibrated probability back rather than a paragraph, keeps the threshold and the policy in a data file, and writes every decision to one ledger.

const outcome = await ask({
  decision: "completion-check",
  state: { task, taskParts, claimedResult, receipts },
});

if (outcome.action === "accept") deliver(result);
else redispatch(outcome.answers);   // it did not do the work, and now you know

Typed questions

A choice, a yes or no, or a score. A probability comes back, not prose to parse.

Policy as data

How sure is sure enough, and what happens otherwise, lives in one file you can read.

One ledger

Every judgment, its confidence, and what the software did about it. Auditable.

Swappable judge

A hosted model today, our own tomorrow, plain code where the answer is a fact.

The measurement that matters

The first decision we shipped is the one above: did the agent actually do the work? It was measured once, against thirty cases written by someone who never saw the questions and never saw a result, with no tuning afterwards. A test you can retake until you pass is not a test.

Why it works: ask small questions

This is the lesson that produced those numbers, and it is worth more than the code. Asking a model one question about a whole task scored in the seventies. Splitting the same judgment into one question per part of the task, settling the parts that are facts in code, and adding them up in code, scored perfectly.

Give the model the judgment in the middle. Keep the arithmetic. Whether a file exists at a path, whether every part passed, whether a count exceeds a budget: none of those need a model, and asking one makes them worse.

What this changed for a real customer

An MSP owner in our beta asked Titan a question he already knew the answer to: which local stores carry a particular hot-dip galvanized bolt in packs of ten or twenty-five. He knew the answer was awkward, because nobody packages it that way.

The difference is not a better model. It is a handful of rules about evidence, and a check that the finished answer honours them.

The part we did not build

Later that week the same customer pasted a network scan of his own home network and asked Titan what it thought. Titan read every open port, explained which were normal, and made five recommendations. The first one was this:

Outside-in scan, the one test these scans cannot do. From a phone hotspot, off your network, run the same scan against your public address. Everything internal being clean does not verify the edge by itself.

Titan, unprompted, as recommendation one

Nobody asked it for that. There was no scan-reading skill on that machine; we checked the logs afterwards and the feature we thought was responsible had not shipped yet. What the agent had was four standing rules about evidence, the same four that turned the bolt question around, and it applied them to a network instead of a hardware store.

A day earlier, the same agent had written itself a playbook: how to pin an exact specification before searching, what to do when a catalogue does not list a part, and the rule that "not shown" is a finding rather than a blank. It named its own past failures as the proven cases. We did not write that file and we did not ask for it.

That is the shape of the thing. Teach an agent how evidence works, give it a place to check its own claims, and keep the receipts. It gets better at your work rather than louder about it.

Why it is open

The mechanism is not the moat. Anyone can ask a model a typed question. What is hard, and what takes months of real customer work to accumulate, is knowing which questions to ask, what wording survives contact, where the thresholds belong, and having a ledger of decisions to learn from.

So the engine is MIT licensed and public. If it stops another team from shipping an agent that confidently reports work it never did, that is a good outcome for everyone.
